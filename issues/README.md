# issues — задачи для CLI

Одна задача = один файл = один чат CLI = одна ветка = один PR.

## Именование

```
{NN}-{область}-{краткое-название}.md
```

`NN` — сквозной номер, не переиспользуется. Область: `infra`, `sync`, `points`,
`drivers`, `miniapp`, `admin`, `bot`.

Пример: `03-points-ledger-core.md`

## Жизненный цикл

```
issues/03-points-ledger-core.md      ← активная задача
issues/done/03-points-ledger-core.md ← закрытая, перемещается после мержа
```

Файл не удаляется — он остаётся историей того, что и зачем было сделано.
При закрытии дописывается секция «Результат»: что фактически сделано,
чем отличается от плана, что всплыло по ходу.

## Правила

- Задача пишется **до** начала работы, не по факту
- Если по ходу выяснилось, что задача больше, чем казалась — не растягивать,
  а закрыть по критерию готовности и завести следующую
- Секция «Не делать» обязательна. Без неё задача расползается
- Продуктовые решения в issue не принимаются. Если задача упирается
  в продуктовый вопрос — он идёт в `../product/`, а issue ждёт
