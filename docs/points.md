# Принципы: баллы

## Баланс — производная, а не значение

Баланс водителя определяется журналом операций. Поле с текущим балансом
существует как кэш и обновляется только вместе с записью в журнал,
в одной транзакции.

**Прямое изменение баланса запрещено везде**, кроме сервиса, который пишет журнал.

Почему это принцип, а не деталь реализации: в старом проекте баланс правили
пять независимых мест, журнала не было, и на вопрос «откуда у водителя столько
баллов» ответить было нечем. Это же породило гонку между фоновыми задачами —
одна инкрементировала на стороне базы, другая писала прочитанное ранее значение,
и начисления затирались.

## Каждая операция идемпотентна

У операции есть ключ, по которому она однозначно опознаётся, и уникальное
ограничение в базе на этот ключ. Повторная попытка не создаёт вторую запись.

Схема ключей — контракт между задачами, поэтому фиксируется здесь:

| Операция | Ключ |
|---|---|
| перенос баланса при запуске журнала | `opening:<driver_id>` |
| начисление за поездку | `trip:<trip_id>` |
| приветственный бонус | `welcome:<driver_id>` |
| списание при заказе | `order_spend:<order_id>` |
| возврат при отмене | `order_refund:<order_id>` |
| ручная правка | `manual:<uuid>` |
| доначисление по перепроверке | `recon:<trip_id>` |

**Новую схему ключа придумывать нельзя.** Нужна — сначала правка этой таблицы,
потом код.

Что из этого следует бесплатно: воркеры можно запускать параллельно,
глобальный мьютекс не нужен, ретраи безопасны, окна опроса можно перекрывать,
повторное нажатие «отменить» не возвращает баллы дважды.

Три бага старого проекта закрываются этим одним решением — гонка за балансом,
двойной возврат при повторной отмене, повторное начисление при перекрытии окон.

## Инвариант

Сумма операций журнала по водителю равна его текущему балансу.
Расхождение означает, что кто-то пишет мимо журнала.

Проверяется регулярно. На переходный период, пока жив старый бот, расхождение
ожидаемо — сверка сообщает, но не исправляет.

## Начисление за поездки

Балл начисляется за завершённую поездку, один раз за поездку, навсегда.

Окно опроса внешнего API строится **по времени завершения** поездки,
а не по времени бронирования, и перекрывается с предыдущим. Это то место,
где старый проект терял пятую часть поездок — подробности в `analysis.md`.

Курс — 1 балл за поездку, независимо от суммы и длительности. Это продуктовое
решение, унаследованное как есть; пересмотр обсуждается в `../product/`.

## Исправление прошлого

Перепроверка работает в два шага и никогда не начисляет автоматически:
сначала отчёт о расхождениях, потом осознанное применение, с возможностью
выборки по водителю или периоду.

Балл, появившийся у водителя неожиданно — это разговор с диспетчерской,
которого можно избежать, просто не начисляя молча.
