# Принципы: водитель

## Идентичность

Водитель существует в трёх системах и связывается тремя ключами:
профиль во внешнем API парка (источник правды по факту работы), телефон
(мост между парком и мессенджером при первой регистрации) и идентификатор чата
(канал доставки и авторизация).

Водители и сотрудники — независимые сущности, между собой не связаны.

## Телефон подтверждает только сам владелец

**Контакт принимается, только если он принадлежит отправителю.**

Это принцип, а не проверка на всякий случай. В старом проекте телефон читался
из присланного контакта без сверки с отправителем, а кнопка «отправить контакт» —
не единственный способ прислать контакт: через скрепку прикладывается любой
контакт из адресной книги.

Дальше срабатывала ветка «водитель найден по телефону — привязываем к нему
текущий чат», и аккаунт чужого водителя переезжал на отправителя вместе
со всеми накопленными баллами. Настоящий водитель терял доступ.

Для этого достаточно знать номер телефона коллеги. Ни технических знаний,
ни специальных инструментов.

## Перепривязка — операция, а не побочный эффект

Смена чата у существующего водителя не происходит молча внутри регистрации.
Это отдельное действие: с записью в журнал, с уведомлением на прежний чат,
с возможностью потом разобраться, кто и когда это сделал.

## Приветственный бонус

Начисляется после нескольких завершённых поездок, один раз за водителя.
Идёт через журнал операций на общих основаниях — см. `points.md`.

## Что не переносим

Счётчик дней без поездок в старом проекте считал не дни без поездок,
а дни простоя самого бота: инкремент шёл по разнице с отметкой последней
проверки, а отметка двигалась каждый прогон. Значения в сотни дней
у большинства водителей — следы периодов, когда синхронизация не работала.

Такое поле нельзя показывать в интерфейсе и нельзя переносить как есть.
