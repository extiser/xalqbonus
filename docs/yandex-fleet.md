# Справка: Yandex Fleet API

Документация внешней системы — единственный тип документа, который здесь уместен
подробно: чужой API нашим кодом не документируется.

**Статус: пусто.** Заполняется на этапе 1 по результатам разведки
(`issues/02-sync-fleet-api-recon.md`) — контракт с реальным примером ответа,
проверенный на живом API, а не восстановленный по чужим обёрткам.

## Что должно здесь появиться

- эндпоинт получения заказов парка: тело запроса, форма ответа, пример
- поля заказа, которые нам нужны, и как они называются на самом деле
- поведение пагинации
- что приходит для заказов в промежуточных статусах
- лимиты: сколько запросов в час, что возвращается при превышении
- поведение при ошибках, включая ответ 200 с кодом ошибки в теле

## Что известно до разведки

Действующий бот использует получение заказов **по каждому водителю отдельно**
и фильтрует по времени бронирования. Гипотеза, на которой построена новая схема:
тот же эндпоинт принимает запрос без указания водителя и умеет фильтровать
по времени завершения. Основание — сторонняя обёртка к этому API,
не официальная документация.

Пока гипотеза не проверена, план синхронизации остаётся планом.
