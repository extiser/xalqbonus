## Общие справочники (enum)

Эти перечисления используются сразу в нескольких эндпоинтах группы Cars. Ниже приведены полные списки значений (дословно из документации).

### CarStatuses / ParkProfile.status — статус ТС

| Значение | Описание |
|----------|----------|
| `unknown` | статус неизвестен |
| `working` | в данный момент используется для совершения поездок |
| `not_working` | не используется для совершения поездок |
| `repairing` | подвергается техническому обслуживанию или ремонту |
| `no_driver` | за машиной не закреплён водитель |
| `pending` | ведётся обработка сведений об автомобиле |

### Amenities — удобства в ТС (25 значений)

```
conditioner, no_smoking, child_chair, animal_transport, universal,
wifi, check, card, yamoney, newspaper, coupon, creditcard,
dont_call, smoking, delivery, vip_event, woman_driver,
post_terminal, bicycle, skiing, passenger_plus, cargo_clean,
door_to_door, sticker, lightbox
```

### Categories — категории ТС (19 значений)

```
econom, comfort, comfort_plus, business, minivan, vip, wagon,
pool, start, standart, ultimate, maybach, promo, premium_van,
premium_suv, suv, personal_driver, express, cargo
```

### ColorEnum — цвет ТС (13 значений, русскими словами)

```
Белый, Желтый, Бежевый, Черный, Голубой, Серый, Красный,
Оранжевый, Синий, Зеленый, Коричневый, Фиолетовый, Розовый
```

### Transmission — тип коробки передач

```
mechanical, automatic, robotic, variator
```

### OwnershipType — тип собственности

```
park, leasing
```

### FuelType — тип топлива

```
petrol, methane, propane, electricity
```

### VehicleField — поля автомобиля (для `fields.car` в списке)

```
id, status, amenities, category, callsign, brand, model,
year, color, number, registration_cert, vin
```

## Общая структура ошибок

Все эндпоинты обеих групп возвращают ошибки в одном формате (`application/json`):

```json
{
  "code": "example",
  "message": "Текстовое описание ошибки"
}
```

| Параметр | Тип | Описание |
|----------|-----|----------|
| `code` | string | Машиночитаемый код ошибки |
| `message` | string | Человекочитаемое сообщение об ошибке |

Стандартные коды:

| Код | Описание |
|-----|----------|
| 400 | Некорректные параметры запроса |
| 401 | Отсутствуют параметры авторизации запроса |
| 403 | Недостаточно прав для выполнения запроса |
| 404 | Запрашиваемый ресурс не найден |
| 429 | Превышено допустимое число запросов |
| 500 | Внутренняя ошибка сервера |

Какие именно коды объявлены у каждого эндпоинта — указано в соответствующем разделе.

## 1. POST /v1/parks/cars/list — Получение списка автомобилей

**Группа:** Cars
**URL:** `POST https://fleet-api.taxi.yandex.net/v1/parks/cars/list`
**Описание:** Получение списка автомобилей с поддержкой фильтрации и пагинации.

### Заголовки

| Параметр | Тип | Обяз. | Описание | Ограничения |
|----------|-----|:-----:|----------|-------------|
| `X-API-Key` | string | Да | API-ключ | Мин. длина: 1 |
| `X-Client-ID` | string | Да | Идентификатор клиента | Мин. длина: 1 |

Query-параметров и path-параметров нет. Идентификатор парка передаётся в теле (`query.park.id`).

### Тело запроса

```json
{
  "limit": 100,
  "offset": 0,
  "query": {
    "park": {
      "id": "ee6f33c4562b4e1f8646d157bd70b2c4",
      "car": {
        "id": ["5011ade6ba054dfdb7143c8cc9460dbc"],
        "status": ["working"],
        "amenities": ["wifi"],
        "categories": ["econom"],
        "is_rental": true
      }
    },
    "text": ""
  },
  "fields": {
    "car": ["color"]
  }
}
```

#### Корневой уровень

| Параметр | Тип | Обяз. | Описание | Ограничения |
|----------|-----|:-----:|----------|-------------|
| `limit` | integer | Нет | Ограничение на число автомобилей в ответе | По умолчанию: 1000; мин: 1; макс: 1000 |
| `offset` | integer | Нет | Отступ для пагинации | По умолчанию: 0; мин: 0 |
| `query` | object | Нет | Поисковые ограничения | — |
| `fields` | object | Нет | Данные для извлечения | — |

#### `query.park`

| Параметр | Тип | Обяз. | Описание | Ограничения |
|----------|-----|:-----:|----------|-------------|
| `id` | string | **Да** | Идентификатор партнёра | Мин. длина: 1; макс: 100 |
| `car` | object | Нет | Поисковые ограничения на автомобиль | — |

#### `query.park.car`

| Параметр | Тип | Обяз. | Описание | Ограничения |
|----------|-----|:-----:|----------|-------------|
| `id` | array[string] | Нет | Идентификаторы автомобилей | Мин. элементов: 1; макс: 100 |
| `status` | array[string] | Нет | Статусы автомобилей (см. [CarStatuses](#carstatuses--parkprofilestatus--статус-тс)) | — |
| `amenities` | array[string] | Нет | Удобства в автомобиле (см. [Amenities](#amenities--удобства-в-тс-25-значений)) | — |
| `categories` | array[string] | Нет | Категории автомобилей (см. [Categories](#categories--категории-тс-19-значений)) | — |
| `is_rental` | boolean | Нет | Парковая машина | — |

#### `query.text`

| Параметр | Тип | Обяз. | Описание |
|----------|-----|:-----:|----------|
| `text` | string | Нет | Текстовый поисковый запрос |

#### `fields`

| Параметр | Тип | Обяз. | Описание |
|----------|-----|:-----:|----------|
| `car` | array[string] | Нет | Поля автомобиля для извлечения (см. [VehicleField](#vehiclefield--поля-автомобиля-для-fieldscar-в-списке)) |

### Ответ 200 OK

```json
{
  "limit": 100,
  "offset": 0,
  "total": 357,
  "cars": [
    {
      "id": "2111ade6gk054dfdb9iu8c8cc9460mks",
      "status": "working",
      "amenities": ["wifi"],
      "category": ["econom"],
      "callsign": "123456789",
      "brand": "Mercedes-Benz",
      "model": "E-klasse",
      "year": 2019,
      "color": "Черный",
      "number": "Т8654Т99",
      "registration_cert": "123456789",
      "vin": "12345678909876543"
    }
  ]
}
```

| Параметр | Тип | Описание | Ограничения |
|----------|-----|----------|-------------|
| `limit` | integer | Ограничение на число автомобилей | мин: 1; макс: 1000 |
| `offset` | integer | Отступ пагинации | мин: 0 |
| `total` | integer | Общее число автомобилей, удовлетворяющих запросу | мин: 0 |
| `cars` | array[Vehicle] | Массив автомобилей | — |

#### Объект `Vehicle`

| Параметр | Тип | Описание |
|----------|-----|----------|
| `id` | string | Идентификатор ТС |
| `status` | string | Статус ТС |
| `amenities` | array[string] | Удобства в ТС |
| `category` | array[string] | Категории ТС |
| `callsign` | string | Позывной |
| `brand` | string | Марка ТС |
| `model` | string | Модель ТС |
| `year` | integer | Год выпуска ТС |
| `color` | string | Цвет ТС |
| `number` | string | Государственный регистрационный номер |
| `registration_cert` | string | Номер свидетельства о регистрации ТС |
| `vin` | string | VIN (обязательно для России) |

### Пагинация

Классическая offset-пагинация:

- `limit` — от 1 до 1000, по умолчанию 1000;
- `offset` — от 0, по умолчанию 0;
- `total` в ответе — общее число записей, удовлетворяющих фильтру.

Обход всего парка: увеличивать `offset` на `limit`, пока `offset + len(cars) < total`.

### Коды ошибок

400, 401, 403, 429, 500 — формат см. [Общая структура ошибок](#общая-структура-ошибок).

## Разбор: что такое «условия работы» (driver work rules)

> Этот раздел важен для проекта: в старой системе поле «условия работы» встречается у водителей, и от него может зависеть право на бонусы.

### Что даёт API (проверенные факты)

1. **Условия работы — справочник уровня парка, а не уровня водителя.** Эндпоинт принимает `park_id` и возвращает список правил этого парка. Каждый водитель ссылается на одну запись из этого справочника.
2. **Структура записи минимальна: `id` + `name` + `is_enabled`.** Никаких ставок, процентов комиссии, сумм аренды или лимитов через этот эндпоинт **не отдаётся**. То есть по API мы видим только *название* условия работы и *факт*, что оно активно.
3. **Значения не перечислимы (нет enum).** Названия правил парк придумывает сам. Пример из документации — `Штатный`. Типичные наименования в реальных парках: `Штатный`, `Аренда`, `Личный автомобиль`, `Комиссия N%`, `Самозанятый`, `Курьер` и т.п. — но это **не фиксированный список**, у каждого парка свой набор.
4. **`is_enabled = false` не означает, что правило удалено.** Отключённые условия остаются в справочнике (их нельзя назначать новым водителям), но исторически привязанные к ним водители/транзакции сохраняются. При обработке нужно учитывать оба состояния.
5. **Идентификатор — 32-символьный hex-UUID без дефисов**, как и остальные ID в Fleet API (`06640a5568bf4c238324d34fd1769a64`).

### Что означает «условие работы» по смыслу

Условие работы (work rule) — это **тарифный план парка для водителя**: набор финансовых правил, по которым парк рассчитывается с конкретным водителем. Оно определяет, какая комиссия удерживается парком с заказа, есть ли аренда автомобиля и на каких условиях, как и с какой периодичностью происходят выплаты, какие удержания и лимиты применяются. Один парк заводит несколько таких правил (например, отдельно для водителей на своей машине и отдельно для арендаторов парковых машин) и привязывает каждого водителя ровно к одному.

### Практические выводы для системы бонусов

- **Условие работы — это естественный признак сегментации водителей для бонусной программы.** Водитель на аренде и водитель на собственном авто зарабатывают по разной экономике, поэтому логично, что правила начисления бонусов могут (и, скорее всего, должны) различаться по `work_rule_id`.
- **В качестве ключа в нашей БД надо хранить `work_rule_id`, а не `name`.** Название парк может переименовать в любой момент — идентификатор стабилен.
- **`name` стоит хранить как денормализованную подпись** для отображения в админке и в правилах начисления, обновляя её при периодической синхронизации справочника.
- **Синхронизация справочника — редкая и дешёвая операция:** один GET без пагинации на парк. Достаточно обновлять кэш раз в сутки или по требованию из админки.
- **Ограничение:** экономические параметры правила (процент комиссии, сумма аренды) через Fleet API недоступны — их придётся либо задавать вручную в нашей системе, либо выводить косвенно из транзакций водителя.

### Что осталось непроверенным

Страница `Drivers`/`DriverProfiles` с эндпоинтом получения списка водителей в рамках этой задачи не открывалась (перебор слагов дал 404), поэтому точное имя поля-ссылки в профиле водителя (ожидаемо `work_rule_id` внутри `ParkProfile` профиля водителя) **не подтверждено документально**. Это нужно проверить при сборе документации по группе водителей — там же должно быть видно, обязательно ли поле и можно ли фильтровать список водителей по условию работы.
