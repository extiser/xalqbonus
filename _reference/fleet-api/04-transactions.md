# Yandex Fleet API — группа Transactions

Собрано с https://fleet.yandex.ru/docs/api/ru/openapi/Transactions/ — 7 страниц, все получены с первой попытки.

Базовый хост API: `https://fleet-api.taxi.yandex.net`

**Контекст проекта:** транзакции Fleet API — это **деньги на балансе водителя в системе Яндекса**, а не наши внутренние бонусные баллы. См. раздел [Выводы для бонусной программы](#выводы-для-бонусной-программы) в конце.

---

## Содержание

| # | Метод | Путь | Назначение |
|---|-------|------|-----------|
| 1 | POST | `/v2/parks/driver-profiles/transactions/list` | Список транзакций по водителю/курьеру |
| 2 | POST | `/v2/parks/orders/transactions/list` | Список транзакций по заказам |
| 3 | POST | `/v2/parks/transactions/list` | Список транзакций по парку |
| 4 | POST | `/v2/parks/transactions/categories/list` | Список категорий транзакций |
| 5 | POST | `/v3/parks/driver-profiles/transactions` | Создание транзакции на балансе водителя |
| 6 | GET | `/v3/parks/driver-profiles/transactions/status` | Статус транзакции |
| 7 | POST | `/v2/parks/driver-profiles/transactions` | Создание транзакции (**устаревший**) |

## Общие элементы

### Заголовки авторизации (все эндпоинты)

| Заголовок | Тип | Обязательность | Описание | Ограничения |
|-----------|-----|----------------|----------|-------------|
| `X-API-Key` | string | Да | «API-ключ» | Min length: 1 |
| `X-Client-ID` | string | Да | «Идентификатор клиента» | Min length: 1 |
| `Accept-Language` | string | Нет | «Предпочитаемый язык ответа» | Min length: 2; пример `ru` |

`Accept-Language` присутствует на всех эндпоинтах `/v2/*`. На `/v3/*` эндпоинтах в документации указаны только `X-API-Key`, `X-Client-ID` и (для создания) `X-Idempotency-Token`.

### Общие коды ошибок

| Код | Описание (дословно) |
|-----|---------------------|
| 400 | «Некорректные параметры запроса» |
| 401 | «Отсутствуют параметры авторизации запроса» |
| 403 | «Недостаточно прав для выполнения запроса» |
| 429 | «Превышено допустимое число запросов» |
| 500 | «Внутренняя ошибка сервера» |

> Примечание: на `/v3/*` эндпоинтах код 401 в документации не указан — перечислены 400, 403, 429, 500.

Тело ошибки одинаково для всех кодов:

```json
{
  "code": "example",
  "message": "Текстовое описание ошибки"
}
```

| Поле | Тип | Описание |
|------|-----|----------|
| `code` | string | «Машиночитаемый код ошибки» |
| `message` | string | «Человекочитаемое сообщение об ошибке» |

**Список конкретных машиночитаемых значений `code` в документации не приводится** — ни на одной из 7 страниц.

### Общие типы

| Тип | Описание | Ограничения |
|-----|----------|-------------|
| `ParkId` | «Идентификатор партнёра» | string, min 1, max 100 |
| `DriverProfileId` / `ContractorProfileId` | «Идентификатор водителя» / «Идентификатор исполнителя» | string, min 1, max 100 |
| `OrderId` | «Идентификатор заказа» | string, min 1, max 100 |
| `TransactionId` | Идентификатор транзакции | string, min 1, max 100 |
| `TransactionCategoryId` | «Категория транзакции. Допустимые значения можно получить через API /v2/parks/transactions/categories/list» | string, min 1, max 100 |
| `TransactionCategoryName` | «Локализованное название категории транзакции» | string, min 1, max 100 |
| `Amount` (v2, в выдаче) | «Сумма с фиксированной точностью» | string, max length 20 |
| `Amount` (v3) | Сумма | string, pattern `^-?[0-9]+(\.[0-9]{1,4})?$` |
| `CurrencyCode` | Код валюты | string, пример `RUB` |
| `DateTime` | «ISO 8601 с временной зоной» | пример `2019-08-08T11:58:01+03:00` |
| `SafeString` | Безопасная строка | string, 1–1000 символов |
| `FleetExternalBusinessEventId` | «Идентификатор события, инициирующий создание транзакций через api» | string, min length 1 |

### Объект `Transaction` (единый для всех трёх list-эндпоинтов)

| Поле | Тип | Описание | Ограничения |
|------|-----|----------|-------------|
| `id` | TransactionId | Идентификатор транзакции | min 1, max 100 |
| `event_at` | DateTime | Время события, «ISO 8601 с временной зоной» | `2019-08-08T11:58:01+03:00` |
| `category_id` | TransactionCategoryId | «Категория транзакции» | min 1, max 100 |
| `category_name` | TransactionCategoryName | «Локализованное название категории транзакции» | min 1, max 100 |
| `amount` | Amount | «Сумма с фиксированной точностью» | max length 20 |
| `currency_code` | CurrencyCode | Код валюты | пример `RUB` |
| `description` | Description | Описание транзакции | — |
| `created_by` | TransactionCreatedBy | Кто создал транзакцию (union из 4 вариантов) | — |
| `driver_profile_id` | DriverProfileId | «Идентификатор водителя» | min 1, max 100 |
| `order_id` | OrderId | «Идентификатор заказа» | min 1, max 100 |
| `event_id` | FleetExternalBusinessEventId | «Идентификатор события, инициирующий создание транзакций через api» | min length 1 |

Пример:

```json
{
  "id": "100200400",
  "event_at": "2019-08-08T11:58:01+03:00",
  "category_id": "partner_service_manual",
  "category_name": "Платежи по расписанию",
  "amount": "12345.1434",
  "currency_code": "RUB",
  "description": "Списание №13",
  "created_by": {
    "identity": "dispatcher",
    "passport_uid": "123456789",
    "dispatcher_id": "3621b3429ea04d989adf5ff4d5515d6a",
    "dispatcher_name": "Вася Пупкин"
  },
  "driver_profile_id": "33de650c6a1a40bfa78dd981817da866",
  "order_id": "c8d40acf182b4b32af72f6ad2029031b",
  "event_id": "ee6f33c4562b4e1f8646d157bd70b2c4"
}
```

### `TransactionCreatedBy` — union из 4 вариантов

Дискриминатор — поле `identity`. Полный набор значений (enum целиком): `dispatcher`, `tech-support`, `fleet-api`, `platform`.

**1. `TransactionCreatedByDispatcher`** — создано диспетчером в веб-интерфейсе:

```json
{
  "identity": "dispatcher",
  "passport_uid": "123456789",
  "dispatcher_id": "3621b3429ea04d989adf5ff4d5515d6a",
  "dispatcher_name": "Вася Пупкин"
}
```

| Поле | Тип |
|------|-----|
| `identity` | const `"dispatcher"` |
| `passport_uid` | PassportUID (string) |
| `dispatcher_id` | DispatcherID (string) |
| `dispatcher_name` | DispatcherName (string) |

**2. `TransactionCreatedByTechSupport`** — создано техподдержкой Яндекса:

```json
{ "identity": "tech-support" }
```

**3. `TransactionCreatedByFleetAPI`** — создано через Fleet API (то есть нашей интеграцией):

```json
{
  "identity": "fleet-api",
  "client_id": "taxi/park/abc123",
  "key_id": "521"
}
```

| Поле | Тип | Пример |
|------|-----|--------|
| `identity` | const `"fleet-api"` | — |
| `client_id` | FleetAPIClientID (string) | `taxi/park/abc123` |
| `key_id` | FleetAPIKeyID (string) | `521` |

**4. `TransactionCreatedByPlatform`** — создано самой платформой (автоматические начисления по заказам, комиссии и т.п.):

```json
{ "identity": "platform" }
```

> Практический смысл для нас: по `created_by.identity == "fleet-api"` можно отличать транзакции, созданные нашей собственной интеграцией, от платформенных и ручных.

## 1. POST `/v2/parks/driver-profiles/transactions/list`

**Описание:** «Получение списка транзакций по водителю (курьеру)»

Страница: `.../Transactions/v2parksdriver-profilestransactionslist-post`

### Тело запроса (application/json)

Корневой объект:

| Параметр | Тип | Обязательность | Описание | Ограничения |
|----------|-----|----------------|----------|-------------|
| `query` | ParksParksDriverProfilesTransactionsListQuery | Да | Объект запроса | — |
| `limit` | TransactionsListLimit | Нет | «Ограничение сверху на число транзакций в ответе» | default 40; min 1; max 1000 |
| `cursor` | RequestCursor | Нет | «Курсор для получения следующий порции данных, значение должно быть взято из ответа на предыдущий запрос» | min length 1 |

`query.park` (обязательный):

| Параметр | Тип | Обязательность | Описание | Ограничения |
|----------|-----|----------------|----------|-------------|
| `id` | ParkId | Да | «Идентификатор партнёра» | min 1, max 100 |
| `driver_profile` | ...QueryParkDriverProfile | Да | Фильтр по водителю | — |
| `transaction` | ListQueryParkTransaction | Нет | Фильтр по транзакциям | — |

`query.park.driver_profile` (обязательный):

| Параметр | Тип | Обязательность | Описание | Ограничения |
|----------|-----|----------------|----------|-------------|
| `id` | DriverProfileId | Да | «Идентификатор водителя» | min 1, max 100 |

`query.park.transaction` (опциональный):

| Параметр | Тип | Описание | Ограничения |
|----------|-----|----------|-------------|
| `event_at` | DateTimeInterval | Интервал времени событий | — |
| `category_ids` | TransactionCategoryIds | «Массив неповторяющихся идентификаторов категорий транзакций» | min items 1; max items 100 |

`DateTimeInterval`:

| Поле | Тип | Обязательность | Формат |
|------|-----|----------------|--------|
| `from` | DateTime | Нет | ISO 8601 с временной зоной |
| `to` | DateTime | Нет | ISO 8601 с временной зоной |

`TransactionCategoryIds` — массив строк `TransactionCategoryId`, каждая min 1 / max 100 символов, min items 1, max items 100. Допустимые значения берутся из эндпоинта № 4.

Пример запроса:

```json
{
  "query": {
    "park": {
      "id": "ee6f33c4562b4e1f8646d157bd70b2c4",
      "driver_profile": {
        "id": "33de650c6a1a40bfa78dd981817da866"
      },
      "transaction": {
        "event_at": {
          "from": "2019-08-08T11:58:01+03:00",
          "to": "2019-09-08T11:58:01+03:00"
        },
        "category_ids": ["partner_service_manual"]
      }
    }
  },
  "limit": 40,
  "cursor": "example"
}
```

### Ответ 200 OK

| Поле | Тип | Описание |
|------|-----|----------|
| `transactions` | ParksTransactionsList | Массив объектов `Transaction` (см. общий раздел) |
| `limit` | TransactionsListLimit | «Ограничение сверху на число транзакций в ответе» (default 40, min 1, max 1000) |
| `cursor` | ResponseCursor | «Курсор для получения следующий порции данных» |

### Пагинация

Курсорная. `limit` — default **40**, min **1**, max **1000**. Значение `cursor` из ответа передаётся в `cursor` следующего запроса.

### Коды ошибок

400, 401, 403, 429, 500 — см. общий раздел.

### Идемпотентность

Не упоминается (эндпоинт на чтение).

## 4. POST `/v2/parks/transactions/categories/list`

**Описание:** «Получение списка категорий транзакций»

Страница: `.../Transactions/v2parkstransactionscategorieslist-post`

Это справочный эндпоинт: именно он даёт допустимые значения `category_id` для фильтрации (№ 1, № 3) и для создания транзакций через устаревший v2 (№ 7).

### Тело запроса (application/json)

`query.park` (обязательный):

| Поле | Тип | Описание | Ограничения |
|------|-----|----------|-------------|
| `id` | ParkId | «Идентификатор партнёра» | min 1, max 100 |

`query.category` (фильтры, опциональные):

| Поле | Тип | Описание (дословно) |
|------|-----|---------------------|
| `is_enabled` | boolean | «Включена ли категория транзакции false бывает только для партнёрских категорий» |
| `is_editable` | boolean | «Доступно ли редактирование категории транзакции true для партнёрских категорий» |
| `is_creatable` | boolean | «Доступно ли создание транзакции в категории» |
| `is_affecting_driver_balance` | boolean | «Влияет ли транзакция в категории на баланс водителя» |

Пример запроса:

```json
{
  "query": {
    "park": {
      "id": "ee6f33c4562b4e1f8646d157bd70b2c4"
    },
    "category": {
      "is_enabled": true,
      "is_editable": true,
      "is_creatable": true,
      "is_affecting_driver_balance": true
    }
  }
}
```

### Ответ 200 OK

| Поле | Тип |
|------|-----|
| `categories` | TransactionCategory[] |

`TransactionCategory`:

| Поле | Тип | Описание | Ограничения |
|------|-----|----------|-------------|
| `id` | string | «Категория транзакции. Допустимые значения можно получить через API /v2/parks/transactions/categories/list» | min 1, max 100 |
| `name` | string | «Локализованное название категории транзакции» | min 1, max 100 |
| `group_id` | string | «Группа категории транзакции» | min 1, max 100 |
| `group_name` | string | «Локализованное название группы категории транзакции» | min 1, max 100 |
| `is_enabled` | boolean | «Включена ли категория транзакции» | — |
| `is_editable` | boolean | «Доступно ли редактирование категории транзакции» | — |
| `is_creatable` | boolean | «Доступно ли создание транзакции в категории» | — |
| `is_affecting_driver_balance` | boolean | «Влияет ли транзакция в категории на баланс водителя» | — |

```json
{
  "categories": [
    {
      "id": "partner_service_manual",

    }

```

### Enum `TransactionCategoryGroupId` (группы категорий) — целиком

| `group_id` | Смысл |
|------------|-------|
| `cash_collected` | Наличные |
| `platform_card` | Оплата по карте |
| `platform_corporate` | Корпоративная оплата |
| `platform_promotion` | Промоакции |
| `platform_bonus` | Бонус |
| `platform_tip` | Чаевые |
| `platform_fees` | Комиссии платформы |
| `partner_fees` | Комиссии партнёра |
| `partner_other` | Прочие платежи партнёра |
| `platform_other` | Прочие платежи платформы |
| `partner_rides` | Платежи по поездкам партнёра |

**Важно:** сам список `category_id` (в отличие от групп) — **не фиксированный enum**. Единственный `id`, приведённый в примерах документации, — `partner_service_manual` («Платежи по расписанию», группа `partner_other`).

### Пагинация

Отсутствует — возвращается весь список категорий парка.

### Коды ошибок

400, 401, 403, 429, 500 — см. общий раздел.

## Выводы для бонусной программы

### (1) Чтение истории денежных операций как сигнала активности — ДА, полноценно доступно

- Три независимых среза: по водителю (№ 1), по заказам (№ 2), по всему парку (№ 3).
- Для **регулярной синхронизации** оптимален № 3 `/v2/parks/transactions/list`: курсорная пагинация, `limit` до **1000** за запрос, фильтр `event_at.from` даёт инкрементальную выгрузку «всё, что появилось с прошлого раза». Пер-водительский № 1 — для точечных запросов (карточка водителя в нашем интерфейсе).
- Каждая транзакция несёт `driver_profile_id`, `order_id`, `event_at`, `category_id`/`category_name`, `amount`, `currency_code` и `created_by`. Этого достаточно, чтобы строить сигналы активности: объём заработка за период, число оплаченных заказов, структура списаний (аренда, штрафы, топливо), доля наличных vs безнал по группам категорий.
- Фильтр `category_ids` (до 100 значений) плюс справочник № 4 с флагом `is_affecting_driver_balance` позволяют отделить операции, реально двигающие баланс, от технических.
- Группировка по `group_id` (11 фиксированных групп: `cash_collected`, `platform_card`, `platform_corporate`, `platform_promotion`, `platform_bonus`, `platform_tip`, `platform_fees`, `partner_fees`, `partner_other`, `platform_other`, `partner_rides`) даёт готовую разметку доходов/расходов без ручной классификации.
- Ограничения: № 2 (по заказам) **без пагинации** и максимум 100 `order_id` за запрос — для массовой выгрузки не подходит. Общий rate limit есть (429), но пороги не опубликованы — нужен бэкофф и запас по частоте опроса.

### (2) Начисление денег водителю через API — ДА, это штатная возможность

- `POST /v3/parks/driver-profiles/transactions` начисляет (`amount` со знаком `+`) или списывает (`-`) реальные деньги на балансе водителя. Сумма — до 4 знаков после точки, ноль запрещён.
- Есть **специально предназначенный вид** `data.kind = "bonus"` с полями `orders_count` (за сколько заказов) и `receipt_condition` (текстовое условие получения) — то есть Яндекс сам предусмотрел сценарий «премия водителю за выполнение условия». Также есть `kind: "referal"` (`parent_driver_id`, `child_driver_id`, `required_orders_count`) — готовая механика «приведи друга».
- Это делает реальной альтернативу внутренним баллам: вместо «баллов в нашем приложении» начислять живые рубли на баланс водителя в Яндексе. Плюс — вознаграждение мгновенно ликвидно и видно водителю в родном приложении; минус — теряется управляемость (баллы можно сжечь/пересчитать, деньги — нет) и возникают налоговые/бухгалтерские последствия, которых у внутренних баллов нет.

### Ограничения на создание транзакций — что нужно учесть

| Ограничение | Статус по документации |
|-------------|------------------------|
| **Идемпотентность** | **Обязательна.** `X-Idempotency-Token`, 16–64 печатных ASCII, и в v3, и в устаревшем v2. Без него запрос не пройдёт. Токен надо детерминированно выводить из нашего внутреннего id начисления, иначе ретрай задвоит деньги. |
| **Категории/виды** | В v3 — **ровно 11 фиксированных `kind`**, произвольную категорию задать нельзя; для бонусов — `bonus` (либо `other` с текстовым `reason`). В устаревшем v2 — `category_id` из справочника парка, обязательно с `is_creatable = true`. |
| **Лимиты на сумму** | Верхний потолок **нигде не документирован**. Формально ограничены только формат (`^-?[0-9]+(\.[0-9]{1,4})?$`) и запрет нуля. Реальные лимиты, вероятно, задаются настройками парка — требуется проверка на тестовом ключе. |
| **Отдельное разрешение** | **Явно не документировано.** В спецификации есть только 403 «Недостаточно прав для выполнения запроса». Практически это означает, что права привязаны к API-ключу/клиенту и, скорее всего, выдаются при подключении Fleet API — уточнять у Яндекса, а не выводить из спеки. |
| **Асинхронность** | 200 OK ≠ деньги зачислены. Ответ отдаёт `status` из `in_progress` / `success` / `fail`; финал опрашивается через `GET /v3/.../transactions/status` по `id` + `version`. Нашей системе нужен воркер до-подтверждения и обработка `fail`. |
| **Защита от ухода в минус** | `condition.balance_min` — транзакция не выполнится, если баланс уйдёт ниже порога. Для начислений неважно, для списаний обязательно. |
| **Версионирование** | Поле `version` позволяет **изменить уже созданную транзакцию**, но только поля суммы (`amount`, `fee_amount`, `park_fee`); `condition` при обновлении не применяется. Полноценного «отмены» в спецификации нет — корректировка делается новой транзакцией с обратным знаком либо повышением версии. |
| **Rate limit** | Есть (429), пороги не опубликованы. |

### Рекомендация по архитектуре

Внутренние баллы стоит оставить основной валютой программы (управляемость, отсутствие налоговых последствий, возможность произвольных правил), а v3-эндпоинт использовать как **опциональный канал выплаты** — «обменять баллы на рубли на баланс Яндекса». Тогда `kind: "bonus"` с `receipt_condition` = описание нашей акции, `X-Idempotency-Token` = наш id выплаты, статус до-подтверждается воркером. Чтение транзакций (№ 3, инкрементально по `event_at.from`) при этом идёт независимо и питает движок правил сигналами реальной активности.
