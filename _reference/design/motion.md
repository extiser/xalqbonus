# Живой фон главного экрана — параметры

Анимированная масса под балансом на главном экране Mini App. Реализация —
`app/main-screen.html`; здесь зафиксированы значения и причины,
по которым они такие.

## Как устроено

Четыре слоя в зоне шапки, все `position: absolute`, контейнер `overflow: hidden`:

| Слой | Размер | Размытие | Цвет ядра | Движение |
|---|---|---|---|---|
| базовое ядро | 420×340 | 52 px | `rgba(150,26,58,0.45)` | нет, неподвижно |
| `blob-core` | 380×360 | 38 px | `rgba(214,38,78,0.92)` | 13 с |
| `blob-wine` | 320×320 | 44 px | `rgba(122,26,92,0.86)` | 17 с |
| `blob-amber` | 300×280 | 48 px | `rgba(206,112,30,0.70)` | 23 с |

Сверху — затемнение вниз, привязанное к низу блока, а не к доле: прозрачное до 45 %, 0.86 фона
за 104 px до низа, полный фон за 68 px (`linear-gradient(180deg, rgba(11,13,17,0) 45%,
rgba(11,13,17,0.86) calc(100% - 104px), #0B0D11 calc(100% - 68px))`, как в эталоне
`app/main-screen.html`), чтобы полка товаров не начиналась посреди зарева. До 24-09-2026 здесь
стояло «от 52 % до 100 %» — отстало от эталона, найдено CLI в PR #206

Каждый подвижный слой — свой `@keyframes` с четырьмя точками: сдвиг по X в пределах
примерно 240 px, по Y до 116 px, масштаб 0.88–1.26, прозрачность 0.62–1.0.
Анимируются только `transform` и `opacity`; `filter: blur` задан статично, поэтому
размытие считается один раз, а дальше слой едет готовой текстурой — это идёт
на видеокарте и не греет процессор на дешёвых телефонах.

## Почему так

**Периоды 13 / 17 / 23 секунды — взаимно простые.** Слои не сходятся в одну фазу,
картинка не повторяется, и не возникает заметного «дыхания в такт».

**Ход большой, размытие умеренное.** Первая версия имела размытие 46–58 px при сдвиге
около 50 px — анимация шла, но разница между кадрами через 5 секунд составляла
28 из 255 по максимуму, то есть движение было физически незаметно. После правки —
91 из 255 при том же интервале. Правило: сдвиг должен в несколько раз превышать
радиус размытия, иначе движения не видно.

**Неподвижное базовое ядро обязательно.** Без него в моменты, когда подвижные слои
расходятся по краям, экран на несколько секунд проваливался почти в чёрный.

**`prefers-reduced-motion: reduce` выключает движение** — остаётся статичная масса.

## Чем проверять

Движение оценивается не на глаз, а сравнением двух кадров с паузой:

```
p.screenshot(path='p1.png'); p.wait_for_timeout(4000); p.screenshot(path='p2.png')
```

и попиксельной разницей. Ориентир для этого фона — максимум около 90 из 255,
среднее около 5. Ниже 30 по максимуму движение считается незаметным.

**В редакторе макетов анимация не проигрывается** — артборд выглядит статичным.
Смотреть только в браузере, файлом `app/main-screen.html`.
